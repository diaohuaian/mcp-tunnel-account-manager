# VERIFY_FAILED 回滚：诊断与安全切换修复

本说明对应 `main` 分支的源码修复，**不是**对已有 `v1.2.0-preview.2` 标签、ZIP、校验清单或冻结核心源码哈希的替换。历史发行附件不自动包含此修复。

## 为什么会回滚

切换是原子操作：所有被明确选中的目标都必须通过配置指纹、进程身份和隧道控制平面认证校验，才能提交新的活动账号；任意目标失败，都按逆序恢复已经发生的变更。

本次故障中，Overleaf 与 Antigravity 的独立真实校验可以通过；失败目标是可选的 DSH ChatGPT Bridge：

- 当前 DSH 为 `0.2.2-rc.1`，已安装 `dsh-chatgpt-bridge@0.6.0` 声明要求 `0.2.0-rc.2`。
- 宿主以 `incompatible-version` 拒绝激活插件；Bridge 的本机 HTTP MCP 入口没有监听。
- tunnel-client 启动后等待该上游及 OAuth 发现，最终不能取得就绪证据（`RUNTIME_NOT_READY`）。
- 旧版界面只显示 `VERIFY_FAILED`，没有说明是哪项服务、哪一层校验失败，因此看起来像全部服务都有问题。回滚本身是在保护已有配置，不应取消。

此结论来自故障机器的插件状态、监听检查和真实隧道诊断；**不是**声称所有 `VERIFY_FAILED` 都由 Bridge 或这个版本组合引起。

## 改了什么

1. **无副作用的本机 HTTP 上游预检**：在准备阶段，对回环 HTTP/HTTPS MCP 地址做有界 TCP 连接检查。常规超时 1 秒，上限 3 秒；不发送任何应用数据、路径、查询参数、请求头或凭据。上游不可达时，在配置写入、进程切换前返回 `TARGET_VERIFICATION_UNAVAILABLE / HTTP_UPSTREAM_UNREACHABLE`。
2. **不把端口可达当作成功**：TCP 预检只是依赖可达性检查；远端上游可能经过代理，不能用直连判断。原有严格认证证据、受支持 tunnel-client 版本、时间新鲜度、目标账号/控制平面、配置指纹、OS 进程身份和回滚回执仍然必须通过；空或部分 probe 结果不能通过验证。
3. **可定位且脱敏的失败信息**：持久化目标服务和固定白名单原因码；界面展示中文说明。原始错误、URL、HTTP 头和密钥不进入新增公开诊断。全局或提交阶段错误不会被错误归因给最后一个服务；恢复回滚不覆盖已保存的原因。
4. **兼容旧账号库**：SQLite 仅增添可空诊断字段；既有加密凭据和历史操作保留。旧失败记录没有的新证据不会被补造，界面仍能以通用错误显示。

## 本机采用的安全处理

用户明确选择暂不使用不兼容的 Bridge：只将该 MCP 的 `enabled` 设为 `false`，保留其配置、加密定义、账号凭据与授权；明确选择 Overleaf 和 Antigravity 两个目标执行切换。

- 不自动跳过请求中的失败目标。
- 不删除或清空 Bridge，不强制启用不兼容插件，不增加版本豁免。
- 不替换真正的 MCP 上游，不放宽健康、认证或进程所有权检查。
- Bridge 日后只有在宿主与插件确实兼容、上游启动并可用后，才应由用户重新启用并单独验证。

禁用参与是故障机器的配置选择，不是源码里针对 Bridge 的永久特判。其他电脑应根据自己的插件兼容性和所需目标决定。

## 验证方式与边界

```powershell
npm.cmd run check
npm.cmd run test:all
npm.cmd run test:release
```

Windows PowerShell 中使用 `npm.cmd` 可避免默认执行策略拦截 `npm.ps1`，不需要修改系统执行策略。

新增回归覆盖本机预检零应用字节/有界超时、失败前无配置和进程变更、认证证据不完整必须失败、目标归因与逆序补偿、诊断脱敏、旧库迁移和界面回退。

完整回归还校正了在本次改动前即能复现的旧测试夹具：异步 action 读取、启动器委派、工作项类型与不存在记录的严格路由、权威进程检查、运行状态嵌套，以及 carrier token 对同一幂等键的绑定。使用隔离密钥库及合成进程身份；没有跳过测试或放松生产安全规则。

自动化测试不能代替真实服务验收。真实切换应使用已有生产 runner 和适配器，检查操作最终为 `SUCCEEDED`、活动账号持久化，并重新核对被禁用 Bridge 的配置与凭据未变。此修复不代表完成 Overleaf 项目读写/推送/编译、Antigravity 业务任务或 Bridge 端到端验收。

## 更新与回退注意事项

更新前停用且核实控制台进程身份，确认没有待处理操作或恢复门禁，备份一致的加密 SQLite 账号库和将替换的源码；密钥留在本机，不上传 GitHub。默认账号库位于 `%LOCALAPPDATA%\McpTunnelAccountManager`。

源码修复涉及控制台及浏览器脚本，重启原控制台并刷新页面后生效。不要同时启动两个实例操作同一账号库。若需回退，先停止并核实进程，再使用更新前的源码和一致备份；不要在运行中覆盖数据库或混用不同时间点的数据库与运行配置。

历史发行构建仍使用固定 RC19 核心基线，不能修改旧基线哈希来伪装成同一发行。若要发布含此修复的新便携包，需要新的构建身份和独立验证。
